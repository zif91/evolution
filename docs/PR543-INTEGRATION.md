## Совместимость событий

При новом событии сначала вызываются его обработчики, затем обработчики старого имени. Старые подписки остаются на прежних ID в БД. В интерфейсе доступны оба имени. Старый плагин видит своё исходное `$modx->event->name`.

| Новое событие | Сохранённое старое событие |
|---|---|
| OnBeforeDocSave | OnBeforeDocFormSave |
| OnDocSave | OnDocFormSave |
| OnBeforeDocDelete | OnBeforeDocFormDelete |
| OnDocDelete | OnDocFormDelete |
| OnDocUndelete | OnDocFormUnDelete |
| OnDocPublish | OnDocPublished |
| OnDocUnpublish | OnDocUnPublished |

Сохранены `mode=new/upd`, `id`, `doc`, `docid`, `children`. До сохранения `doc` ссылается на изменяемый `documentData`; PHP-плагин может менять `$modx->event->params['doc']`. Прямой вызов старого имени работает как раньше и не запускает новое имя. Это односторонний переходный слой. Если один плагин подписан на оба имени, он получит оба вызова; при миграции подписку нужно переносить, а не дублировать.

Update-seeder добавляет новые имена без переименования старых ID; повторный запуск не создаёт дублей. При обновлении существующего сайта требуется штатный установщик в режиме обновления БД. Простая замена vendor не добавляет события в интерфейс. На локальном стенде update-seeder применён отдельно после резервной копии БД.

## Исправления поверх авторских PR

В отдельном форке DocumentManager:

- Пустые поля расписания сохраняют выбранное состояние публикации.
- Явный `null` очищает TV; отсутствие ключа сохраняет значение; значение по умолчанию удаляет override.
- После изменения и копирования групп пересчитываются `privatemgr` и `privateweb`.
- При переносе под удалённого родителя записывается правильный массив данных.
- `events=false` передаётся вложенным операциям копирования; очистка кэша откладывается до завершения копирования.

В Evolution:

- Слой старых событий и сохранение их ID при установке/обновлении.
- Проверки доступа при прямом POST к закрытому ресурсу/родителю; закрытые TV не принимаются от пользователя без прав, в том числе при подмене формы.
- Исправлена константа URL в переходе «сохранить и открыть предпросмотр».
- Разрешены конфликты с текущей `3.1.x`: сохранение TV и `closeActions` в JavaScript менеджера.

## Воспроизведение

Используйте [общую инструкцию стенда](../UPGRADE-LARAVEL-13.md), затем:

```sh
python3 tests/run.py
```

Только для изолированной БД `evolution_lara13_test`. Проверки:

- 31 базовый интеграционный сценарий Illuminate/Evo.
- 19 сценариев DocumentManager: сохранение, TV, группы, копирование, события, старый PHP-плагин, защита системной страницы, дерево и update-seeder.
- 14 HTTP-сценариев настоящих процессоров: cookie/CSRF, создание/редактирование/TV, права отдельного редактора, публикация, копирование, удаление/восстановление, предпросмотр и отказ гостю.
- Загрузка классов, консольные команды, миграции и публикация assets.
- Отдельно `tests/browser.js`: 10 сценариев реального браузера с DocLister, FormLister и сохранением страницы.

HTTP-набор запускает PHP-сервер на свободном loopback-порту, создаёт временного редактора/роль/TV/ресурсы и удаляет их в `finally`. Во время этого набора `seostrict` временно выключен, поскольку PHP router не эмулирует Apache rewrite/filter_input; настройка возвращается после теста. Проверка Apache/Nginx rewrite не входит в эти результаты.

Общая совместимость всех дополнений, всех 43 изменённых файлов процессоров и производственной нагрузки не гарантируется: основное функциональное покрытие относится к ресурсам и событиям. Документировать найденные проблемы следует с версией PHP, дополнений, действием, ожидаемым результатом и ошибкой без секретов.
